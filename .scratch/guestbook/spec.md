# Spec: 미니 방명록 — 글 비밀번호 잠금 + UI 개선

Status: ready-for-agent

## Problem Statement

방문자는 회원가입 없이 방명록에 글을 남기고, 글 비밀번호로 자기 글만 수정·삭제하고 싶다. 지금은 작성·조회·수정·삭제와 비밀번호 확인은 되지만, 틀린 비밀번호를 끝없이 넣어 볼 수 있어서 짧은 글 비밀번호는 무차별 대입으로 쉽게 뚫린다. 또 화면이 기본 스타일에 가까워 밋밋하고, 성공했는지 실패했는지가 한눈에 들어오지 않는다.

## Solution

한 요청자가 한 글에 실패 시도를 5회 하면 그 요청자는 그 글을 20분간 수정·삭제할 수 없게 잠금을 건다. 실패할 때마다 남은 시도를 알려 주고, 잠겼을 때는 남은 시간을 알려 준다. 화면은 깔끔한 모던 카드 스타일로 바꾼다. 작성자 이름 아바타, 상대 시간, 아이콘 버튼, 그라데이션 헤더와 개발자 배지를 넣고, 성공은 토스트 알림으로 보여 준다.

## User Stories

### 글 작성
1. As a 방문자, I want 작성자 이름, 메시지, 글 비밀번호만 입력해 글을 남기기, so that 가입 없이 바로 방명록을 쓸 수 있다
2. As a 방문자, I want 작성자 이름이 1~30자가 아니면 거부되기, so that 비어 있거나 지나치게 긴 이름이 목록을 망치지 않는다
3. As a 방문자, I want 메시지가 1~500자가 아니면 거부되기, so that 빈 글이나 도배성 글이 남지 않는다
4. As a 방문자, I want 글 비밀번호가 4~50자가 아니면 거부되기, so that 너무 쉬운 비밀번호를 정하지 않는다
5. As a 방문자, I want 공백만 입력한 이름이나 메시지가 거부되기, so that 사실상 빈 글이 남지 않는다
6. As a 방문자, I want 이름과 메시지의 앞뒤 공백이 정리되어 저장되기, so that 목록이 깔끔하다
7. As a 방문자, I want 입력이 잘못되면 무엇이 잘못됐는지 폼 아래에 안내받기, so that 바로 고쳐서 다시 낼 수 있다
8. As a 방문자, I want 글이 등록되면 "글이 등록되었습니다" 토스트를 보기, so that 성공했음을 확실히 안다
9. As a 방문자, I want 등록 후 폼이 비워지고 내 글이 목록 맨 위에 나타나기, so that 결과를 바로 확인할 수 있다
10. As a 방문자, I want 등록 중에는 버튼이 비활성화되기, so that 실수로 두 번 등록하지 않는다

### 글 조회
11. As a 방문자, I want 모든 글을 작성 시각 최신순으로 한 페이지에서 보기, so that 최근 글부터 읽을 수 있다
12. As a 방문자, I want 각 글에서 작성자 이름, 메시지, 작성 시각을 보기, so that 누가 언제 무엇을 남겼는지 안다
13. As a 방문자, I want 작성 시각을 "3분 전"처럼 상대 시간으로 보고, 마우스를 올리면 정확한 한국 시간을 보기, so that 한눈에 최근 정도를 알면서도 정확한 시각도 확인할 수 있다
14. As a 방문자, I want 작성자 이름 첫 글자로 된 색깔 아바타를 보기, so that 글쓴이를 시각적으로 구분할 수 있다
15. As a 방문자, I want 수정된 글에 "(수정됨)" 표시를 보기, so that 원래 글이 바뀌었음을 안다
16. As a 방문자, I want 수정된 글이 목록에서 자리를 옮기지 않기, so that 목록 순서가 작성 순으로 일관된다
17. As a 방문자, I want 글이 없을 때 "아직 글이 없습니다" 안내를 보기, so that 화면이 고장 난 게 아님을 안다
18. As a 방문자, I want 목록을 불러오지 못하면 안내를 보기, so that 잠시 후 다시 시도하면 된다는 걸 안다
19. As a 방문자, I want 줄바꿈과 긴 단어가 카드 밖으로 넘치지 않고 보이기, so that 메시지가 원래 모양대로 읽힌다
20. As a 채점자, I want 헤더에서 개발자 이름과 학번을 배지로 바로 보기, so that 누가 만든 과제인지 즉시 확인할 수 있다

### 글 수정
21. As a 글쓴이, I want 글의 수정 아이콘을 눌러 메시지를 고치고 글 비밀번호를 입력해 저장하기, so that 내가 쓴 글의 오타를 고칠 수 있다
22. As a 글쓴이, I want 메시지만 수정할 수 있고 작성자 이름·글 비밀번호·작성 시각은 바뀌지 않기, so that 글의 정체성이 유지된다
23. As a 글쓴이, I want 수정 성공 시 "글이 수정되었습니다" 토스트를 보기, so that 저장됐음을 안다
24. As a 글쓴이, I want 수정 중 취소를 누르면 원래 메시지가 그대로 남기, so that 실수로 바꾸지 않는다
25. As a 요청자, I want 틀린 글 비밀번호로 수정하면 거부되고 "비밀번호가 일치하지 않습니다. (남은 시도 N회)"를 그 글 아래에서 보기, so that 몇 번 더 시도할 수 있는지 안다
26. As a 요청자, I want 수정 메시지가 1~500자가 아니면 거부되기, so that 빈 메시지로 바뀌지 않는다

### 글 삭제
27. As a 글쓴이, I want 글의 삭제 아이콘을 누르고 글 비밀번호를 입력해 "삭제 확인"을 누르면 글이 완전히 삭제되기, so that 원하지 않는 글을 없앨 수 있다
28. As a 글쓴이, I want 삭제 성공 시 "글이 삭제되었습니다" 토스트를 보고 목록에서 글이 사라지기, so that 삭제됐음을 안다
29. As a 요청자, I want 틀린 글 비밀번호로 삭제하면 거부되고 남은 시도와 함께 안내받기, so that 남의 글이 지워지지 않았음을 안다
30. As a 요청자, I want 이미 삭제된 글을 수정·삭제하려 하면 "글을 찾을 수 없습니다"를 보기, so that 상황을 이해할 수 있다

### 잠금
31. As a 글쓴이, I want 누군가 내 글에 틀린 비밀번호를 5번 넣으면 그 요청자가 20분간 잠기기, so that 내 글 비밀번호가 무차별 대입으로 뚫리지 않는다
32. As a 글쓴이, I want 남이 내 글에 대해 잠겨도 나는 계속 내 글을 수정·삭제할 수 있기, so that 남이 일부러 내 글을 못 쓰게 만들 수 없다
33. As a 요청자, I want 수정 실패와 삭제 실패가 합쳐서 세어지기, so that 수정과 삭제를 번갈아 가며 제한을 피할 수 없다
34. As a 요청자, I want 5번째로 틀린 순간 "비밀번호가 일치하지 않습니다. 5회 틀려 20분간 잠겼습니다."를 보기, so that 틀렸다는 사실과 잠겼다는 사실을 한 번에 안다
35. As a 잠긴 요청자, I want 수정·삭제를 시도하면 "비밀번호를 5회 틀려 잠겼습니다. 약 N분 후 다시 시도하세요."를 보기, so that 언제 다시 할 수 있는지 안다
36. As a 잠긴 요청자, I want 잠긴 동안에는 맞는 글 비밀번호를 넣어도 거부되기, so that 잠금이 실제로 대입을 막는다
37. As a 요청자, I want 한 글에서 잠겨도 다른 글은 계속 수정·삭제할 수 있기, so that 잠금이 필요 이상으로 넓지 않다
38. As a 요청자, I want 맞는 글 비밀번호로 성공하면 실패 시도가 초기화되기, so that 가끔 오타 낸 것이 쌓여 잠기지 않는다
39. As a 요청자, I want 20분 잠금이 끝나면 남은 시도가 다시 5회가 되기, so that 잠금 후 정상적으로 다시 시도할 수 있다
40. As a 글쓴이, I want 글을 삭제하면 그 글에 대한 실패 시도 기록도 사라지기, so that 쓸모없는 기록이 남지 않는다

### 공통
41. As a 방문자, I want 휴대폰 화면에서도 폼과 카드가 깨지지 않기, so that 어디서든 방명록을 쓸 수 있다
42. As a 방문자, I want 글 비밀번호가 화면이나 응답 어디에도 노출되지 않기, so that 내 비밀번호가 안전하다

## Implementation Decisions

- **데이터 모델:** 글 테이블은 그대로 둔다(이름, 메시지, 글 비밀번호 해시, 작성 시각, 수정 시각). 실패 시도를 기록할 테이블을 새로 둔다. 키는 (글, 요청자)이고, 실패 횟수와 잠금 해제 시각을 가진다. 글이 삭제되면 해당 기록도 함께 삭제된다.
- **테이블 생성:** 기존처럼 첫 요청 때 자동 생성한다. 마이그레이션 도구는 쓰지 않는다.
- **잠금 저장 위치:** 서버리스 환경이라 메모리에 저장하면 요청마다 초기화된다. 그래서 잠금 상태는 Postgres에 저장한다.
- **요청자 식별:** 요청의 `x-forwarded-for` 첫 번째 값(Vercel이 실제 클라이언트 IP로 설정함)을 쓰고, 없으면 `x-real-ip`, 그것도 없으면 "unknown"으로 처리한다. 잠금 범위의 근거는 ADR-0001에 있다.
- **비밀번호 확인 흐름 (수정·삭제 공통):**
  1. 글이 없으면 404를 반환한다.
  2. 이 (글, 요청자)가 잠겨 있으면 해시 비교 없이 429와 남은 분을 반환한다.
  3. 해시가 일치하면 기록을 지우고 작업을 수행한다.
  4. 불일치하면 실패 횟수를 1 올린다. 5회에 도달하면 잠금 해제 시각을 지금 + 20분으로 정하고 429를, 아니면 403과 남은 시도를 반환한다.
  5. 잠금 시각이 지난 기록은 새 시도 때 0부터 다시 센다.
- **API 계약:**
  - `GET /api/entries`: 200, 글 배열(최신순, 해시 제외)
  - `POST /api/entries`: 입력은 `{name, message, password}`. 201은 글, 400은 `{error}`
  - `PATCH /api/entries/:id`: 입력은 `{message, password}`. 200은 글. 400, 404는 `{error}`
  - `DELETE /api/entries/:id`: 입력은 `{password}`. 200은 `{ok:true}`. 400, 404는 `{error}`
  - 비밀번호 불일치는 403과 `{error, remainingAttempts}`
  - 잠김은 429와 `{error, retryAfterMinutes}`
  - 두 경우 모두 `error`는 사용자에게 바로 보여 줄 수 있는 한국어 문장이다.
- **동시성:** 실패 횟수 증가는 한 번의 upsert 문으로 처리해서, 동시에 들어온 요청이 횟수를 덮어쓰지 않게 한다.
- **UI (깔끔한 모던 카드):**
  - 배경은 은은한 그라데이션이고, 카드는 흰 바탕에 둥근 모서리와 부드러운 그림자를 쓰며, 파스텔 계열 포인트 색을 쓴다.
  - 헤더에는 제목과 개발자 이름·학번 배지를 둔다.
  - 글 카드에는 이름 첫 글자 아바타(이름으로 색을 정해 항상 같은 색), 상대 시간(툴팁에 정확한 KST 시각), 아이콘 버튼(수정·삭제)을 둔다.
  - 성공(등록·수정·삭제)은 하단 토스트로 몇 초간 보여 준다. 오류와 잠금 안내는 해당 폼이나 글 아래 빨간 글씨로 보여 준다.
  - 외부 UI 라이브러리 없이 Tailwind만 쓴다.
- **개발자 정보:** 이름 "김태하", 학번 "202204202"를 헤더에 고정 표시한다.

## Testing Decisions

- **테스트 지점은 HTTP API 하나다.** 실행 중인 앱의 `/api/entries` 엔드포인트에 실제 요청을 보내고 응답(상태 코드, 본문)만 검증한다. 내부 함수나 SQL은 직접 테스트하지 않는다.
- **도구:** Vitest와 `fetch`를 쓴다. 대상 주소는 환경변수로 받는다(기본값은 로컬 개발 서버). 실제 Neon DB를 쓰고, 테스트가 만든 글은 테스트가 스스로 삭제한다.
- **요청자 흉내:** 테스트마다 서로 다른 `x-forwarded-for` 값을 보내 요청자를 구분한다. 이렇게 해서 "남이 잠겨도 글쓴이는 가능"과 "다른 글은 영향 없음"을 검증한다.
- **검증할 동작:**
  - 작성과 입력 검증
  - 최신순 조회와 해시 비노출
  - 수정·삭제의 성공과 403(남은 시도 감소)
  - 5회째에 429
  - 잠긴 동안 맞는 비밀번호도 429
  - 다른 요청자와 다른 글은 영향 없음
  - 성공 시 실패 횟수 초기화
  - 수정·삭제 실패의 합산
- **20분 경과 테스트:** 20분을 실제로 기다리는 테스트는 하지 않는다. 잠금 만료 후 초기화는 코드 리뷰로 확인한다.
- **UI:** 테스트 코드 없이, 배포 후 브라우저에서 직접 확인한다.
- **기존 사례(prior art):** 레포에 기존 테스트는 없다. 이 테스트가 첫 사례다.

## Out of Scope

- 회원가입, 로그인, 관리자 기능, 비밀번호 찾기·재설정
- 이름이나 글 비밀번호 수정
- 삭제된 글 복구(숨김 삭제)
- 페이지네이션, 검색, 정렬 옵션
- 글 작성 자체의 도배 방지(작성 횟수 제한, 캡차)
- IP를 바꿔 가며 시도하는 공격 방어
- 다크 모드
- 실시간 갱신(다른 사람이 쓴 글이 자동으로 나타나는 기능)
